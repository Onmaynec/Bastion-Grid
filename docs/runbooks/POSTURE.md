# Учёт уязвимостей v0.7.0

## Импорт

В разделе «Уязвимости» полный admin/lead может импортировать JSON в локальном формате, пример — examples/posture-import.json. Замените asset_id на UUID существующего актива. source — заявленное имя сканера, observed_at — время наблюдения с часовым поясом. Это ручной импорт: источник не проходит криптографическую аутентификацию, vulnerability_id не проверяется во внешней базе, информация помечена manual-import-unverified.

API: POST /api/v1/posture/imports. Пачка содержит 1–100 находок, до 256 KiB канонического JSON. Обязательные поля записи: external_id, asset_id, title, component, component_version, vulnerability_id и severity. Строки ограничены 200 символами. Уровни: info, low, medium, high, critical. Сначала создайте активы в своём тенанте.

Импорт атомарный: ошибка любой записи откатывает новые объекты и аудит всей пачки. Ключ дедупликации — tenant/source/asset_id/external_id. Повтор идентичного нормализованного наблюдения возвращает duplicates без новой записи аудита и изменения workflow. Изменение наблюдения под прежним ключом даёт 409; новое сканирование должно использовать новый external_id. Запись наблюдения после импорта не редактируется. Это не reconciliation снимков: отсутствие находки в новом скане не закрывает предыдущую автоматически, повторное обнаружение не переоткрывает старую находку.

Карточка хранит источник, время наблюдения, хеш нормализованного наблюдения и хеш исходного импортированного документа, автора и время импорта. Исходный документ целиком не сохраняется, поэтому храните его отдельно для сравнения с import_sha256. Хеши подтверждают согласованность с импортированными данными, а не подлинность сканера.

## Приоритет и доступ

GET /api/v1/posture/findings возвращает доступные находки по убыванию priority_score. Вес severity: info=0, low=3, medium=8, high=15, critical=20. Вес умножается на текущую критичность актива 1–5, итог 0–100. Это локальная модель приоритета, не CVSS/EPSS и не прогноз эксплуатации.

Применяются tenant, группы и чувствительность актива. assigned_only дополнительно ограничивает список находками, назначенными текущему субъекту. Список ограничен 500 доступными находками: превышение возвращает 422 вместо скрытого усечения. Пагинация/фильтры этого списка пока не реализованы. Читатель с ролью auditor не изменяет workflow; collector не имеет доступа к разделу.

## План исправления

Кнопка «Исправление» или POST /api/v1/posture/findings/{id}/workflow изменяет status, owner, due_date, reason и необязательный evidence_id. Нужен If-Match. Причина обязательна, до 2000 символов. Ответственный — действующий admin/lead/analyst того же тенанта, имеющий доступ к активу. Срок — дата YYYY-MM-DD либо null. Для remediation_planned срок обязателен. Просрочка считается по UTC-дате и не показывается для fixed/accepted/false_positive.

| Из состояния | Допустимые новые состояния |
|---|---|
| open | investigating, remediation_planned, accepted, false_positive |
| investigating | open, remediation_planned, accepted, false_positive |
| remediation_planned | investigating, mitigated, fixed, accepted |
| mitigated | investigating, remediation_planned, fixed, accepted |
| accepted, fixed, false_positive | investigating |

Сохранение того же состояния разрешено для изменения назначения/срока с записью истории. Обычные изменения доступны admin/lead/analyst в своём scope. Для fixed, accepted и false_positive нужен полный admin/lead. Ограниченный assigned_only пользователь не может переназначить находку другому.

Fixed требует evidence_id существующего доказательства из кейса того же актива. Это ручное подтверждение руководителя с приложенным доказательством, а не автоматическая проверка свежего скана. Accepted и false_positive требуют документированной причины; отдельный quorum или срок принятия риска не реализованы. Возврат в investigating сохраняет прежние записи истории. Последовательность переходов, причины, назначения, сроки и ссылки evidence сохраняются в history и хешируются аудитом.

## Границы и обновление

Схема сервера остаётся 3: находки хранятся как новый вид objects. Остановите старый сервер, сохраните backup и запустите v0.7.0 без init. Старый интерфейс не отображает находки; используйте backup перед обновлением при полном откате.

CycloneDX/SPDX, компоненты/зависимости SBOM, CMDB connectors, webhooks, CVE feed, автоматическое сопоставление версий и подтверждение исправления по свежему скану ещё отсутствуют. Промышленный этап Posture и формальная приёмка RFP остаются открытыми.
