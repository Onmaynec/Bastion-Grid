# Эксплуатация лабораторного стенда

## Первый запуск

Из корня: `python -m bastion init`, затем `python -m bastion serve --lab`. Откройте 127.0.0.1:8080. Ключи находятся в указанном init файле. Не добавляйте его в Git и не вставляйте ключи в issue, URL или скриншот. На Windows ограничьте доступ к `var` средствами NTFS ACL: POSIX chmod не заменяет Windows ACL.

## Синтетический сценарий

В другом терминале запустите `python tools/demo.py`. Скрипт обращается только к указанному API; по умолчанию localhost. Он не запускает процессы на endpoint и не сканирует сеть. Ожидаемые результаты: 12 accepted, 12 duplicates, 4 alerts, APPROVED, execution false. Каждая новая серия имеет отдельный run ID.

## Отзыв доступа

`python -m bastion revoke northstar-lab analyst`. Новые запросы bearer и cookie будут отвергнуты немедленно. Identity записи и история остаются. Удаление ключа из файла само по себе не отзывает существующий сеанс.

## Истечение лабораторных ключей

Ключи истекают через 24 часа. В 0.2.0 ключ ротируется в разделе «Доступ» до истечения с использованием действующего admin. Без действующего admin recovery ещё отсутствует. Для отдельного нового эксперимента используйте другую БД: `python -m bastion --db var/new-lab.sqlite3 init`. Запуск: `python -m bastion --db var/new-lab.sqlite3 serve --lab`. Старую БД сохраняйте для проверки доказательств. Не удаляйте историю ради продления доступа.

## Проверка доказательств

Экспортируйте bundle в разделе «Аудит». Выполните `python -m bastion verify bundle.json`. Для проверки относительно заранее сохранённого доверенного checkpoint добавьте `--checkpoint HEX`. `anchored: false` означает отсутствие внешней точки доверия. Успешная проверка не является независимой цифровой подписью или юридической аттестацией.

## Backup и восстановление

```bash
python -m bastion backup var/backup.sqlite3
python -m bastion --db var/backup.sqlite3 serve --lab --port 8081
```

Backup использует SQLite backup API и поддерживает живую БД. Назначение не должно существовать: случайная перезапись запрещена. На восстановленной копии проверьте кейсы и повторно выгрузите evidence bundle. Ключи подходят, если не истекли; их хеши содержатся в snapshot. Сам backup содержит все tenant data и требует защиты так же, как исходная БД. Не копируйте только основной `.sqlite3` во время работы WAL.

## Worker не обрабатывает события

Проверьте журнал процесса. ACK подтверждает хранение, а не обработку. Ошибка worker откатывает транзакцию; события остаются pending. Исправьте причину, перезапустите сервер, повторная обработка не должна удваивать алерты. Правила, опубликованные после уже обработанных событий, применяются к истории только через replay; replay не создаёт алерты.

## Конфликт версии

HTTP 409 при `If-Match`: обновите карточку и проверьте последнее изменение. Не повторяйте запрос со случайно увеличенным номером версии.

## Недоступный интерфейс

Проверьте Python 3.12+, текущий каталог, порт, наличие `--lab` и точный URL. Host разрешён только localhost/127.0.0.1 с выбранным портом. Сетевой доступ с другого устройства намеренно отсутствует. Для браузерного теста нужен Chromium с разрешёнными локальными системными сокетами; ограниченная среда может запрещать запуск браузера.
