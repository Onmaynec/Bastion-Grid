# Локальный collector v0.4.0

Collector запускается явно в терминале обычного пользователя. Он читает семейство/релиз ОС, архитектуру и версию Python, добавляет свою версию и отправляет endpoint_heartbeat. Не читает журналы ОС, процессы, командные строки, файлы пользователей или сетевые соединения. Службу и автозапуск не устанавливает; команд с сервера не исполняет.

## Настройка

1. Запустите локальный сервер: `python -m bastion serve --lab`.
2. В «Активы» создайте актив и скопируйте UUID из таблицы активов. В «Доступ» создайте запись с ролью collector, сохраните выданный ключ в отдельный текстовый файл `collector-token.txt`. Не используйте ключ администратора.
3. В «Телеметрия» зарегистрируйте source_id `local-endpoint`, выберите эту запись collector и нужный актив.
4. Скопируйте `examples/collector.json` в отдельный локальный каталог вне Git. Замените asset_id на UUID актива. Положите файл ключа рядом с конфигурацией. Пути token_file и spool разрешаются относительно конфигурации, а не текущей рабочей папки.
5. Разрешите доступ к каталогу только своему пользователю: на Linux используйте права 0700 на каталог, 0600 на ключ; на Windows настройте ACL каталога. chmod не заменяет Windows ACL. Очередь **не зашифрована**: используйте только лабораторные данные. Ключ в очереди не хранится.

Из корня репозитория:

```bash
python -m bastion.collector --config /path/to/collector.json sample
python -m bastion.collector --config /path/to/collector.json status
python -m bastion.collector --config /path/to/collector.json flush
python -m bastion.collector --config /path/to/collector.json run --interval 60
```

На Windows укажите свой путь в кавычках и при необходимости замените python на py -3.12. Команда sample сохраняет одно наблюдение без отправки. Flush отправляет до 100 готовых событий; status ничего не отправляет. Run делает sample+flush раз в интервал (5–3600 секунд плюс время работы цикла). Ctrl+C останавливает процесс; очередь остаётся на диске. Секреты не передаются в аргументах командной строки.

## Offline и ACK

По умолчанию очередь хранит до 1000 наблюдений и 4 MiB канонических JSON payload. Опции `--max-events` и `--max-bytes` задаются перед командой и действуют в текущем запуске. Пределы проверяются в одной SQLite-транзакции, включая одновременные запуски. При снижении лимита накопленные данные не удаляются. Новое наблюдение отклоняется с увеличением dropped; sample возвращает код 2.

Ограничение payload не равно ограничению размера файла: SQLite использует страницы и rollback journal; освобождённые страницы переиспользуются. Общий дисковый cap, шифрование, приоритеты и 48-часовой offline-прогон из RFP не реализованы.

ACK должен содержать durable=true и ровно одну положительную sequence в accepted или duplicates. Только после него строка удаляется локально. При потере ACK событие отправляется с прежним ID и содержимым. Ошибочный ответ, недоступность сервера, 408/429/5xx сохраняют событие. Задержки повторов: 1, 2, 4, 8… максимум 256 секунд; для 429 учитывается целочисленный Retry-After до 86400 секунд. Следующая попытка происходит при очередном flush/run после этого времени; фонового таймера в sample/status нет.

Очередь FIFO: заблокированное или ожидающее повтора первое событие удерживает следующие. HTTP 3xx и 4xx, кроме 408/429, требуют вмешательства. Redirect запрещён; proxy из окружения не используется. Допустим только HTTP к числовому 127.0.0.1. mTLS и передача на удалённый сервер не поддерживаются.

## Диагностика и ротация

Status показывает queued, payload_bytes, blocked, next_attempt (Unix timestamp), head.attempts/code, счётчики sampled/accepted/duplicates/dropped/retry_attempts. Это локальные показатели; сервер не получает spool metrics. В консоли видны события endpoint_heartbeat и время последнего приёма источника. Отсутствие heartbeat само по себе не является доказательством компрометации.

При 401 обновите файл ключа после ротации; он читается при каждой отправке. При 403 проверьте роль, политику, привязку и паузу источника. При 409 проверьте конфликт event_id. После устранения причины:

```bash
python -m bastion.collector --config /path/to/collector.json retry-blocked
python -m bastion.collector --config /path/to/collector.json flush
```

Retry-blocked только снимает блокировку, не меняет исходные события. Endpoint/source/asset закреплены в metadata очереди. Их смена с тем же spool запрещена, даже если он пуст: используйте новый файл. Ротация ключа привязку не меняет.

Остановка: Ctrl+C. Удаление: после проверки доставки удалите локальную конфигурацию, ключ и spool, затем отзовите collector в «Доступ». Автозапуска и системных служб, которые требовали бы деинсталляции, нет.

## Обновление сервера

С v0.3.0 схема сервера остаётся 3. Остановите старый сервер и запустите новую версию без init. Схема очереди collector — отдельная версия 1; неизвестная версия отклоняется. Системные службы Windows/Linux, Event Log/ETW/auditd, шифрованная очередь, enrollment/mTLS, подписанные пакеты/обновления и ресурсные прогоны остаются открытыми требованиями.
