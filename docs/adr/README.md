# Реестр архитектурных решений

Решения относятся к версии 0.1.0. Они не отменяют обязательства RFP R2.

## ADR-001 Локальный профиль вместо неподтверждённого production

Выбран явный `serve --lab`, bind только 127.0.0.1. Альтернатива — сразу объявить сервис промышленным с непроверенной IAM/HA-интеграцией. Она отклонена: невозможно подтвердить приёмочные свойства. Последствие: первая поставка используется для локальной проверки логики, M1 не закрыт.

## ADR-002 Python и SQLite для первого исполняемого контура

Python 3.12 и SQLite входят в среду запуска без внешних пакетов. WAL, FULL synchronous, unique constraints и транзакции дают воспроизводимые проверки локальной согласованности. Альтернатива PostgreSQL + broker сохраняется для следующего этапа. Недостатки: общий writer, отсутствие RLS и независимых resource pools, неподходящая архитектура для R1/R2 EPS. Схема хранит JSON объектов для быстрой проверки модели; production требует нормализованных таблиц и миграций.

## ADR-003 Случайные ключи только для лаборатории

OIDC/PKCE не имитируется. Временные credentials выдаёт локальный администратор, secrets не хранятся в БД открыто. Альтернатива локальные пароли отклонена: ненужная password lifecycle и ложное впечатление промышленной IAM. До OIDC нет MFA, federated logout и refresh rotation. Cookie HttpOnly/SameSite, CSRF и проверка revocation применяются уже сейчас.

## ADR-004 Явно ограниченный API

Маршруты `/rules`, `/responses`, `/events/ingest` документируют текущий local API. Альтернатива — публиковать всю поверхность RFP с заглушками — отклонена: успешные ответы на неработающие операции недопустимы. Целевые `/detections/rules` и `/response/requests` будут введены при выделении сервисов. OpenAPI содержит только 22 реализованные операции API, без health/static. Никаких пустых успешных production endpoints нет.

## ADR-005 Приём отдельно от обнаружения

ACK означает committed batch. Worker обрабатывает устойчивую очередь отдельно от запроса. Альтернатива синхронной детекции внутри ingest отклонена из-за увеличения задержки и связи ошибок. Локальная очередь не заменяет Kafka, backpressure и DLQ. Poison events отбрасываются валидатором с откатом всего batch.

## ADR-006 Согласование без исполнения

Сохраняются allowlist, impact, TTL, quorum и версия. Не реализуется ни сетевое воздействие, ни произвольный shell. Альтернатива вызова локальных системных команд из UI отклонена: отсутствуют подписанные агенты и receipt verification. `simulation_only` нельзя отключить пользовательским параметром.

## ADR-007 Проверяемый экспорт с честной границей доверия

SHA-256 chain и связанный manifest проверяются отдельно от сервера. Альтернатива самодельной цифровой подписи отклонена. Пока нет KMS и key lifecycle, signature явно null. Trusted checkpoint должен поступать независимым каналом; защита от привилегированного администратора не заявляется.

## ADR-008 Функциональная консоль без сборочной цепочки

HTML/CSS/JavaScript поставляются вместе с сервером, без CDN и node_modules. Это упрощает офлайн-запуск первого стенда. Альтернатива React/TypeScript остаётся целевым решением при расширении UI. Разметка экранирует динамические значения; CSP запрещает inline scripts. Accessibility audit и браузерная приёмка не завершены.

## ADR-009 Поэтапное развитие Identity

В 0.2.0 поставлены lab identity lifecycle, application ABAC и миграции SQLite. PostgreSQL/RLS и OIDC/MFA не подменяются этими механизмами и остаются открытыми. Альтернатива одновременного подключения непроверенного IdP и новой БД отклонена для текущей поставки: сначала проверяется перенос состояния и единое enforcement связанных объектов. Ограниченные identities не получают глобальные rules/audit/export, поскольку корректное частичное раскрытие audit chain требует отдельного формата доказательств.

## ADR-010 Локальный collector до системных служб

В 0.4.0 проверяется доставка из отдельного процесса: ограниченная SQLite-очередь, стабильный event ID, durable ACK и ротация ключа. Автозапуск и удалённое управление отсутствуют. Шифрование не имитируется самодельной криптографией: очередь явно помечена незашифрованной и предназначена для лабораторных данных. Windows ACL, шифрованный spool, mTLS enrollment и подписанные службы требуют отдельной реализации. Частичные локальные тесты не закрывают WIN/LNX требования.
